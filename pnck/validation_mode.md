# validation_mode.md — 검증 계약서 (후반부)

이 문서는 **PNCK 결합 소분자 설계·검증 과제에서만 유효한 계약**입니다.
환경 설정과 복구 절차는 `CLAUDE.md`에 있습니다.

---

## 1. Role — 누구의 관점인가

아래 중 **하나를 선택해 표시**하십시오. 같은 데이터라도 관점에 따라 Top 3가 달라지는 것이 이 과제의 핵심입니다.

- [ ] **A. Structural biologist** — plausible binding mode가 최우선
- [ ] **B. DMPK / Toxicology** — intended-use exposure와 safety fit이 최우선

| | A. Structural biologist | B. DMPK / Toxicology |
|---|---|---|
| 핵심 질문 | 이 결합 양상이 물리적으로 타당한가 | 의도한 사용 조건에서 안전한가 |
| 주로 보는 근거 | clash, pocket 상호작용, geometry | ADME/T 예측, 불확실성, liability 구조 |
| 중단 판단 | 구조 가설이 서지 않을 때 | DMPK 리스크가 판별 불가할 때 |
| 다음 실험 | binding 검증 실험 | 판별용 DMPK 실험 |

사람의 역할은 **연구 책임자(PI)**이지 코더가 아닙니다.
무엇을 만들지, 언제 멈출지, 어떤 기준이 생물학적으로 타당한지는 사람이 결정합니다.

---

## 2. Goal — 무엇을 결정하는가

PNCK(UniProt Q6P2M8)에 결합하는 small molecule 후보를 설계하고,
**실제로 합성해서 실험해볼 가치가 있는 Top 3**를 선별한다.

최종 산출물은 "가장 점수가 높은 분자"가 아니라 다음 세 가지입니다.

1. Top 3와 각각의 선정 근거
2. 탈락시킨 후보들의 **구체적 탈락 사유** (지표 값 인용)
3. 다음에 수행할 **판별 실험 1가지**와 그것이 구별해주는 가설

---

## 3. Inputs — 어떤 근거가 있는가

| 입력 | 출처 | 비고 |
|---|---|---|
| PNCK 아미노산 서열 | UniProt Q6P2M8 | |
| PNCK 예측 구조 | ESMFold (ESM Atlas) | PDB에 실험 구조 없음 |
| 구조 신뢰도 지표 | pLDDT, confidence score | 신뢰 구간별로 해석을 달리할 것 |
| 타깃 pocket | [결정 후 기록] | 선정 근거를 함께 기록 |
| 생성 분자 | DiffSBDD | [결정 후 기록] 개 |

예측 구조를 입력으로 쓴다는 사실 자체가 결과의 불확실성 요인입니다.
**어느 영역을 신뢰하고 어느 영역을 의심하는지**를 명시적으로 기록하십시오.

---

## 4. Tools — 실제로 쓸 수 있는가

도구를 아는 만큼 지시가 정확해집니다. 모르는 도구는 조사해서 선택하고, **왜 그것을 골랐는지 밝히십시오.**

### 4.1 Pose validity

| 도구 | 확인하는 것 | 보장하지 않는 것 |
|---|---|---|
| PoseBusters | 로딩·화학적 유효성, 분자 내·분자 간 geometry, bond length·angle, 심각한 원자 겹침(clash), 참조 pose와의 RMSD | **높은 binding affinity 아님**, **bioactive conformation 아님** |

### 4.2 Synthetic accessibility — 단독으로 쓰지 말 것

| 도구 | 유형 | 범위 | 쓰는 것 | 놓치는 것 |
|---|---|---|---|---|
| SA Score | 규칙 기반 휴리스틱 | 1 쉬움 → 10 어려움 | fragment 빈도 기여 + 구조 복잡도 페널티 | 실제 반응 경로·재고·시약·조건 인식 없음 |
| SCScore | 신경망 복잡도 랭커 | 1 단순 → 5 복잡 | 반응 생성물을 반응물보다 높게 랭킹하도록 학습 | 반응 코퍼스 편향. 복잡도 ≠ 경로 실현성 |
| RAscore | 플래너 대리 | 0 낮음 → 1 높음 | AiZynthFinder의 solved/unsolved 라벨로 학습한 분류기 | 경로 미제공. 플래너·재고·예산·도메인 편향 상속 |
| AiZynthFinder | 완전 경로 플래너 | 경로 + solved/unsolved | 신경 정책 유도 MCTS로 재고 building block까지 도달 | 느림. 템플릿·재고·탐색 예산에 결과가 좌우됨 |

- 최소 **2개 이상을 함께** 사용하고, **값이 불일치하는 분자를 반드시 표시**하십시오. 불일치 자체가 정보입니다.
- 대량 1차 선별에는 빠른 도구를, 최종 Top 후보에는 경로를 반환하는 도구를 씁니다.

### 4.3 Solubility

assay에서 실제로 사용 가능한 수준인지 판단합니다. 기준값과 근거를 기록하십시오.

### 4.4 ADME/T

| 도구 | 비고 |
|---|---|
| ADMETlab 3.0 | API 제공. 여러 endpoint와 **불확실성 정보**를 함께 반환 |

- 모든 후보를 **동일 조건**으로 비교합니다.
- 경고 구조(structural alert)와 불확실성을 값과 함께 기록합니다.
- 응답이 느리면 배치를 나눠 요청하고, 실패한 배치는 실패로 기록합니다.

## 5. Rules — 어떻게 검토하는가

- 숫자는 실제 실행 결과에서 가져옵니다. 추정치를 결과처럼 쓰지 않습니다.
- 실행하지 않은 검증을 했다고 서술하지 않습니다.
- 도구별로 **버전과 실행 조건**을 기록합니다. 같은 도구도 설정에 따라 값이 달라집니다.
- 지표를 합산해 단일 점수로 만들지 않습니다. 축별로 따로 보고, 탈락은 축 단위로 판단합니다.
- 통과 기준을 사후에 조정해 후보를 살리지 않습니다. 기준을 바꿔야 한다면 먼저 보고하고 그 사실을 기록합니다.
- 예측 구조 기반이라는 한계를 결론에 반드시 반영합니다.

## 6. Output — 무엇을 남기는가

| 산출물 | 내용 |
|---|---|
| `outputs/validation_master.csv` | 분자 ID, SMILES, 축별 지표 값, 계산 도구·버전 |
| `outputs/report.md` | Top 3, 선정 근거, 탈락 사유, 다음 판별 실험, 신뢰할 수 없는 부분 |
| `outputs/traceability.csv` | 보고서의 모든 숫자 → 근거 파일·행 매핑 |
| `outputs/tool_log.md` | 실행한 주요 도구 호출 시간순 정리 |

`report.md`에는 **"이번 분석에서 신뢰할 수 없는 부분과 그 이유"** 절을 반드시 포함합니다.
이 절을 형식적으로 채우는 것은 계약 위반으로 간주합니다.

---

## 7. Stop — 언제 멈추는가

각 단계가 끝나면 결과를 요약하고 다음 단계 진행 여부를 사람에게 묻습니다.
다음 경우에는 진행을 멈추고 보고합니다.

- 외부 서비스(UniProt / ESM Atlas / ADMETlab)가 응답하지 않을 때 — **재시도를 반복하지 말고** 먼저 보고
- 예측 구조의 pocket 영역 pLDDT가 낮아 설계 입력으로 부적절해 보일 때
- 대량 생성 전 소규모 스모크 테스트가 실패했을 때
- 보고서에 인용할 숫자의 근거 파일을 찾을 수 없을 때
- Top 3를 선정하기에 통과 후보가 충분하지 않을 때 — 기준을 낮추지 말고 보고
